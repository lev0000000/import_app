# Import / Export Products

Веб-приложение для асинхронного импорта товаров из XLSX-файлов, хранения данных в MySQL и просмотра каталога товаров.

## Технологии

**Backend:** PHP, Slim 4, Doctrine ORM, MySQL, RabbitMQ, PhpSpreadsheet, PHPUnit.

**Frontend:** Angular, TypeScript, NgRx Store / Effects, Signals, Tailwind CSS.

**Инфраструктура:** Docker, Docker Compose, Nginx, PHP-FPM.

## Возможности

- Загрузка XLSX-файлов с товарами.
- Асинхронная обработка импорта через RabbitMQ.
- Отслеживание статуса импорта.
- Отображение ошибок обработки строк.
- Сохранение товаров, дополнительных атрибутов и изображений.
- Обновление существующих товаров по `external_code`.
- Каталог товаров с серверной пагинацией.
- Поиск по названию и фильтрация по цене.
- Просмотр подробной информации о товаре.

## Требования

Для запуска необходимы:

- Docker Engine
- Docker Compose Plugin
- Git
- Доступ к интернету для загрузки Docker-образов, зависимостей и изображений товаров

Node.js и Composer на хостовой машине не обязательны, если соответствующие зависимости устанавливаются внутри Docker.

## 1. Клонирование проекта

```bash
git clone <REPOSITORY_URL>
cd import_app
```

## 2. Настройка окружения

Создайте файл окружения из примера:

```bash
cp .env.example .env
```

Если backend использует отдельный файл окружения:

```bash
cp server/.env.example server/.env
```

Укажите параметры подключения к MySQL и RabbitMQ согласно конфигурации Docker Compose.

**Важно:** при подключении из контейнера используйте имена Docker-сервисов, а не `localhost`.

Например, если сервис базы данных называется `db`, именно `db` должен использоваться в качестве хоста подключения.

Не добавляйте реальные пароли и файл `.env` в Git.

## 3. Подготовка директорий и прав

Приложению необходим доступ на запись в следующие директории:

| Директория | Назначение |
|---|---|
| `server/uploads/imports` | Временное хранение загруженных XLSX |
| `server/uploads/img` | Хранение изображений товаров |

Создайте директории:

```bash
mkdir -p server/uploads/imports
mkdir -p server/uploads/img
```

Для локального развёртывания можно предоставить владельцу директории права на запись:

```bash
chmod -R u+rwX server/uploads
```

Если PHP работает в Docker от другого пользователя, необходимо предоставить права именно пользователю PHP-процесса.

Проверьте пользователя внутри контейнера:

```bash
docker compose exec app id
```

Здесь `app` — предполагаемое имя PHP-сервиса; при необходимости замените его на фактическое.

При использовании bind mount права на хосте должны позволять контейнерному пользователю создавать и изменять файлы. Для Linux можно назначить соответствующий UID/GID либо настроить ACL.

Не рекомендуется использовать `chmod -R 777`, особенно на публичном сервере.

**Важно:** PHP-приложение и consumer должны использовать общий том с `uploads`, поскольку загруженный XLSX должен быть доступен процессу фонового импорта.

## 4. Запуск Docker

Соберите и запустите контейнеры:

```bash
docker compose up -d --build
```

Проверьте состояние:

```bash
docker compose ps
```

Посмотрите логи:

```bash
docker compose logs -f
```

Дождитесь готовности MySQL и RabbitMQ перед выполнением миграций и запуском импорта.

## 5. Установка зависимостей

Если Composer-зависимости не устанавливаются при сборке PHP-образа, установите их внутри PHP-контейнера:

```bash
docker compose exec app composer install
```

Команду необходимо выполнять из директории, где находится `composer.json`, либо указать рабочую директорию проекта.

Frontend-зависимости устанавливаются через:

```bash
npm ci
```

Если frontend также контейнеризирован, выполняйте установку внутри соответствующего контейнера.

## 6. Миграции базы данных

Проект использует Phinx для управления миграциями.

После запуска MySQL выполните миграции из backend-директории:

```bash
vendor/bin/phinx migrate
```

Если Phinx установлен внутри PHP-контейнера, запускайте команду через `docker compose exec`, учитывая рабочую директорию контейнера.

Миграции создают таблицы товаров, изображений, атрибутов и необходимые таблицы импорта.

## 7. RabbitMQ и фоновый обработчик

Импорт выполняется асинхронно.

После загрузки XLSX backend создаёт задачу импорта и отправляет сообщение в RabbitMQ. Consumer получает сообщение, обрабатывает файл и сохраняет результат в MySQL.

**Consumer должен работать постоянно.**

Убедитесь, что:

- RabbitMQ запущен и доступен backend.
- Consumer подключается к тому же RabbitMQ.
- Consumer имеет доступ к загруженным XLSX.
- Consumer имеет права на запись изображений.
- Consumer автоматически перезапускается после сбоя.

Если consumer описан отдельным сервисом Docker Compose, проверьте его состояние:

```bash
docker compose ps
docker compose logs -f <CONSUMER_SERVICE>
```

Замените `<CONSUMER_SERVICE>` на фактическое имя сервиса.

## 8. Запуск frontend

Если Angular не запускается через Docker, перейдите в его директорию, установите зависимости и запустите сервер разработки:

```bash
npm ci
npx ng serve --host 0.0.0.0
```

Обычно Angular доступен по адресу:

```text
http://localhost:4200
```

Для доступа с другого компьютера в той же сети используйте IP машины, на которой запущено приложение:

```text
http://192.168.1.100:4200
```

IP указан для примера.

Убедитесь, что Angular отправляет API-запросы на адрес backend, доступный из браузера пользователя, а CORS разрешает соответствующий Origin.

Для постоянного размещения рекомендуется собирать Angular в production-режиме и раздавать статические файлы через Nginx.

## 9. Проверка работы

После запуска:

1. Откройте приложение.
2. Перейдите на страницу импорта.
3. Загрузите XLSX-файл.
4. Убедитесь, что задача импорта создана.
5. Дождитесь завершения обработки.
6. Проверьте количество успешно импортированных строк и ошибки.
7. Откройте каталог товаров.
8. Проверьте поиск, фильтрацию и пагинацию.
9. Откройте карточку товара и убедитесь, что изображения и атрибуты отображаются.

Повторный импорт товара с тем же `external_code` должен обновлять существующую запись без создания дубликата.
